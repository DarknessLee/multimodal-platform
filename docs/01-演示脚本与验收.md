## 1. 演示脚本逐条映射（原文 7 步 + 多角色 5 行）

| 原文步骤 | 操作（页面） | 角色账号 | 接口 | 可见结果 |

## 3. 自动化验收

```powershell
# 终端 1
npm run dev

# 终端 2
npm run build     # 后端 tsc + 前端 vue-tsc/vite build
npm run accept    # API 全流程断言（约几十秒）
npm run e2e       # Edge 无头点通全流程 + 截图（需 Playwright Core，用本机 Edge）
```

- `accept` 覆盖：登录 → 下单 → 列表/详情 → 调度 → 公路三段节点 → 海运/铁路节点 →
  轨迹（GPS/司机/港站/EDI）→ 签收 → 出账 → 账单金额核对 → 权限拦截 → 角色过滤。
- `e2e` 覆盖：5 个账号依次登录，从 UI 完成同一票订单的全流程，关键页面截图。

## 4. 排错

| 现象 | 处理 |
|---|---|
| API 启动报 `ECONNREFUSED` | 确认 MySQL 服务已启动；检查 `api/.env` 的账号密码 |
| 登录返回 40102 | 账号/密码错误；演示密码统一为 `demo123` |
| 订单列表为空 | 当前角色无可见订单：换 `mto01` 看全部 |
| 「当前状态不允许该操作」 | 节点顺序错误：按公路接单→提货→送达、海运进场→到港、铁路进场→到站执行 |
| 端口占用 | 改 `api/.env` 的 `PORT` 与 `web/vite.config.ts` 的代理目标 |
| e2e 找不到浏览器 | 脚本使用本机 Edge（channel=msedge）；未安装 Edge 时需安装 |
| 数据想恢复初始 | `npm run db:init` 重置 7 表与演示数据 |

## 5. 演示话术（1 分钟版）

> 这是一个「一票到底」的多式联运演示：货主在 Web 端下单，MTO 看到待调度订单后，
> 人工为公路段选择承运商并一键生成运单与三段运输方案；公路司机在任务里接单、
> 上报提货和送达；港站在海运和铁路段做进场确认与箱况录入，轨迹实时追加；
> 货主随时看到全程 mock 轨迹，到达后在线签收；结算按分段费用一键出账，
> 货主立即能看到明细账单。整套系统只有一个 Web 端，登录不同角色账号即可看到
> 同一票运单的状态如何在角色之间流转。

### 说明与已知项

- `vite build` 提示 chunk > 500KB（Element Plus + ECharts 整包），属演示可接受的体积警告，不影响运行。
