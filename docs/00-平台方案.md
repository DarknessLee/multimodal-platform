# 多式联运供应链协同平台 · 最终方案

> 软件全称：多式联运供应链协同平台（简称：多式联运平台）
> V1.0
> 形态：单 Web 端 + 模块化单体后端 + 本地 MySQL 8，外部系统通过集成适配器接入
> 启动：`npm run setup` → `npm run dev`（API:8080 / Web:5173）

---

## 1. 项目定位

面向多式联运业务的一体化协同平台：以 **MTO（多式联运经营人）** 为核心，拉通货主、货代、公路/铁路/水路承运人、港站、结算、金融、保险、监管与平台运营，
覆盖「**询价 → 报价 → 合同 → 订单 → 智能调度 → 一单制运单 → 公铁水履约 → 箱管/单证/存证 → 签收 → 应收应付 → 对账/发票/支付/保理 → 经营分析 → 集成/监管/运营**」全链路。

外部系统（95306、港口 EDI、CA、银行、税务、保险、监管）通过集成适配器接入；编码、价格、时效与报文结构遵循真实业务标准，可扩展替换为正式系统。

## 2. 技术架构

```
┌──────────────────────────────────────────────────────────────┐
│ Web（Vue 3 + Vite + TS + Element Plus + Pinia + ECharts）      │
│ 受理/订单/调度/履约/箱管/单证/结算/财务/监控/治理/验收          │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTP / JWT
┌──────────────────────────────▼───────────────────────────────┐
│ API（Node 24 + Express 5 + TS + mysql2 + zod）                 │
│ modules: auth master quote contract orderV1 waybill documents  │
│ containers rail sea dispatch capacity monitor alerts iot       │
│ billing reconciliation invoice payment factoring insurance     │
│ analytics integration regulator ops dashboard audit notify     │
│ platform: priceEngine eventBus outbox sequence                 │
└──────────────────────────────┬───────────────────────────────┘
                               │
┌──────────────────────────────▼───────────────────────────────┐
│ MySQL 8（59 张表，utf8mb4/InnoDB，可一键重建种子）              │
│ 外部系统适配：95306/港口EDI/CA/银行/税务/保险/监管/GPS      │
└──────────────────────────────────────────────────────────────┘
```

- **模块化单体**：按领域分模块，接口边界清晰，后续可拆微服务；不引入 Docker/K8s/MQ/ES。
- **集成适配器**：所有外部报文落 `integration_message`，支持失败重试、批量重试、适配器健康检查。
- **存证**：本地哈希链（`sha256(payloadHash|prevHash|blockHeight)`），非真实联盟链。
- **图表**：ECharts 离线渲染，地图为经纬度散点视图，不依赖瓦片服务。

## 6. 功能模块与页面

| 领域 | 页面/能力 |
|---|---|
| 总览 | `/dashboard` KPI/趋势/待办 |
| 受理 | 订单中心、快速下单、报价工作台、合同管理、客户/伙伴/主数据 |
| 调度 | `/dispatch/plans` 三方案（成本/时效/平衡）生成与确认、`/dispatch/board` 调度看板、`/capacity` 运力池 |
| 一单制 | `/waybills` 运单中心、`/waybills/:id` 详情（事件链/分段/箱/单证/存证校验）、`/waybills/:id/track` 跟踪 |
| 履约 | `/tasks` 运输任务、`/terminal` 港站作业、`/containers` 箱管、`/documents` 单证中心、`/rail/tasks`、`/sea/tasks` |
| 监控 | `/monitor` 深色大屏、`/alerts` 预警中心与异常工单 |
| 结算 | `/settlement` 账务、`/bills/:id` 账单详情、`/finance/reconciliations`、`/finance/invoices`、`/finance/payments`、`/finance/factoring`、`/finance/analytics`、`/insurance` |
| 治理 | `/integration/messages` 集成中心、`/regulator` 监管中心/报送/合规、`/ops` 运营后台/配置/任务、`/acceptance` 全链路验收、`/audit/logs` |

核心业务规则：
- **调度**：三方案确定性规则评分（成本/时长/可靠度），确认后事务签发主运单 + 3 张分段运单 + 5 张单证 + 事件 + 存证。
- **一单制**：主单/分段单/箱关联/单证/哈希链存证，事件按交接节点推进。
- **结算**：签收后自动生成应收（客户价+附加费+税额+毛利）与各段承运人应付账单；对账/发票/支付/保理状态机闭环。
- **预警**：温度/开门/停留/延误/偏航规则，ack/close 状态机，CRITICAL 有关联未处置工单时禁止关闭。
- **监管**：报送 DRAFT→SUBMITTED→ACCEPTED/RETURNED；5 类合规检查。

## 7. 数据与接口规范

- 箱号 **ISO 6346** 校验位；统一社会信用代码 **GB 32100**；UN/LOCODE、铁路车站电报码。
- 单据编码：`HT` 合同、`BJ` 报价、`MO` 订单、`WB/SW` 主单/分段单、`DOC` 单证、`BL` 账单、`FP` 发票、`PAY` 支付、`DZ` 对账、`JG` 监管报送、`BX` 保单等。
- 报文：95306 需求车（JT/T 1351 语义）、港口 CODECO/COARRI、电子发票、银行回执、CA 签章、保险、监管回执。
- 时间/金额/税率（9% 增值税）/箱型/线路运价均按业务样例生成。
