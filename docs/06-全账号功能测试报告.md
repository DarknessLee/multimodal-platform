## 2. 测试方法

脚本：`scripts/audit-accounts.mjs`（可重复执行）

1. 用 12 个账号分别登录，读取其权限集合；
2. 从权限菜单目录生成该账号可访问的菜单路由（不再靠手工清单）；
3. 追加有权限的关键详情页（订单、运单、运单跟踪、箱详情、账单、报价、合同），无权限的详情页不纳入巡检；
4. 逐页访问并监听：
   - `pageerror`（页面 JS 异常）；
   - `console`（error 级别日志）；
   - `/api/` 响应状态 ≥400；
   - 页面 `.el-alert--error` 加载错误提示；
   - 是否被重定向到 `/login` 或 `/403`；
5. 失败时保存截图到 `.tmp/account-audit/`，最后汇总退出码。

> 巡检为只读，不写业务数据；写操作由既有 API 验收（217 项）与 UI E2E（38 阶段）覆盖，避免污染种子数据。

## 4. 本轮发现并修复的问题

### 4.1 港站「运单跟踪」菜单 403（真实问题，已修复）

- 现象：`terminal01` 点击左侧「运单跟踪」进入 `/orders?view=track`，被路由守卫重定向到 403；
- 原因：该菜单由 `menu:track` 控制，但 `/orders` 路由只要求 `menu:orders`，港站只有前者；
- 修复：`/orders` 路由权限改为 `['menu:orders', 'menu:track']`（任一即可），`/orders/new`、`/orders/:id` 仍要求 `menu:orders`；
- 验证：港站该页巡检通过；全量 E2E 回归通过。

### 4.2 金融机构保理工作台读取资金方 403（前次已修复，本轮复核）

- 现象：`finance01` 打开保理申请弹窗时请求 `/partners?type=FINANCE...` 403；
- 原因：`GET /partners` 只允许 MTO/ADMIN/FORWARDER；
- 修复：新增只读角色 FINANCE（仅 GET，写操作仍受 `partner:create` 限制）；
- 本轮复核：保理工作台页面与资金方下拉正常，无 403。

### 4.3 巡检误报（非应用问题）

- 部分角色有 `menu:orders` 但没有 `order:create`，直接访问 `/orders/new` 会被 403；
- 这是**预期权限控制**，已从巡检范围中剔除（仅对有 `order:create` 的角色测试下单页）。

## 6. 复现命令

```powershell
npm run setup
npm run dev

# 全账号只读巡检（另开终端）
npm run audit:accounts

# 全量功能回归
npm run accept:all
npm run e2e:all
npm run build
```

> `audit:accounts` 需要 API/Web 已启动，建议先 `npm run db:init` 使用干净种子；巡检结束不会写业务数据。

## 7. 说明与边界

- 本巡检覆盖“每个账号可见的菜单页 + 有权限的关键详情页”；按钮级写操作由 217 项 API 验收与 38 阶段 UI E2E 覆盖，未逐一重复点击所有按钮，避免污染种子数据。
- 授权范围外的直接 URL 返回 403 是预期安全行为，不计为缺陷。
- 若后续新增菜单/页面，按 `scripts/audit-accounts.mjs` 的权限目录机制会自动纳入（菜单常量新增即可）。
