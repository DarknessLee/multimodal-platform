## 2. 多角色模型（单 Web 端，登录不同账号演示流转）

5 个角色、5 个演示账号（密码均 `demo123`）：

| 账号 | 角色 | 职责 / 演示动作 |
|---|---|---|
| `shipper01` | 货主 SHIPPER | 下单、查看全程轨迹、签收、查看账单 |
| `mto01` | MTO 调度 MTO | 查看新订单、人工分配公路段承运商 |
| `carrier01` | 公路承运人 CARRIER | 我的运输任务：接单 → 已提货 → 已送达 |
| `terminal01` | 港站 TERMINAL | 确认进场、录入箱况、到港/到站确认 |
| `settlement01` | 结算 SETTLEMENT | 对已签收订单生成分段账单 |

同一票订单在各角色间流转：
`货主下单(待调度) → MTO 调度(已调度) → 司机接单/提货(运输中) → 港站进场/到港(节点追加) → 货主签收(已签收) → 结算出账(已出账)`。

### 状态机

- **订单**：`CREATED 待调度 → DISPATCHED 已调度 → IN_TRANSIT 运输中 → ARRIVED 已到达 → SIGNED 已签收 → BILLED 已出账`
- **运单**：`PENDING 待发运 → IN_TRANSIT 运输中 → ARRIVED 已到达 → SIGNED 已签收`
- **分段**：`PENDING → ACCEPTED 已接单 → IN_TRANSIT 运输中 → ARRIVED 已到达 → COMPLETED 已完成`（按 seq 顺序，禁止跳段）
- **账单**：`ISSUED 已出账 → PAID 已支付`（演示不支付）
- **箱**：`EMPTY → GATE_IN 已进场 → LOADED → IN_TRANSIT → ARRIVED → DELIVERED`

### 分段与角色动作

订单默认路线：**上海嘉定 → 上海洋山港（公路）→ 武汉阳逻港（海运）→ 成都城厢站（铁路）**

| 分段 | 动作 | 角色 | 结果 |
|---|---|---|---|
| 公路段 | `ACCEPT` 接单 | 承运人 | ACCEPTED |
| 公路段 | `DEPART` 已提货 | 承运人 | IN_TRANSIT，订单→运输中，追加 GPS 轨迹 |
| 公路段 | `ARRIVE` 已送达港口 | 承运人 | ARRIVED→COMPLETED |
| 海运/铁路段 | `GATE_IN` 确认进场（可录箱况） | 港站 | IN_TRANSIT，追加 EDI/轨迹 |
| 海运/铁路段 | `ARRIVE` 到港/到站 | 港站 | ARRIVED→COMPLETED，触发下一段 |
| 铁路段完成 | — | — | 运单/订单 → 已到达，货主可签收 |
| 运单 | `sign` 签收 | 货主 | 运单/订单 → 已签收 |
| 订单 | `settle` 生成账单 | 结算 | 订单 → 已出账，货主可见账单 |

## 4. 接口（10 个，≤10）

统一 `/api` 前缀；除登录外均需 `Authorization: Bearer <JWT>`；响应 `{code, message, data}`。

| # | 接口 | 角色 |
|---|---|---|
| 1 | `POST /api/auth/login` | 公开 |
| 2 | `POST /api/orders` 下单 | 货主 |
| 3 | `GET /api/orders` 列表（按角色过滤） | 全部 |
| 4 | `GET /api/orders/{id}` 聚合详情 | 全部 |
| 5 | `POST /api/orders/{id}/dispatch` 调度 | MTO |
| 6 | `POST /api/segments/{id}/status` 节点上报/推进 | 承运人 / 港站 |
| 7 | `GET /api/waybills/{id}/track` 轨迹 | 全部 |
| 8 | `POST /api/waybills/{id}/sign` 签收 | 货主 |
| 9 | `GET /api/bills/{id}` 分段账单 | 全部 |
| 10 | `POST /api/orders/{id}/settle` 出账 | 结算 |

## 7. 启动与验收

```
npm run setup     # 装 api/web/e2e 依赖 → 建表 → 写入 5 账号 + 2 条历史订单（幂等）
npm run dev       # API :8080 + 前端 :5173（Vite 代理 /api）
```

- 验收 1：按 `docs/01` 用 5 个账号点通演示全流程；
- 验收 2：curl 登录 + 下单 + 查轨迹（README 附命令）；
- 验收 3：`npm run accept` 自动串流程并逐步断言；
- 验收 4：`npm run build` 零错误；
- 验收 5：`npm run e2e` 用本机 Edge 无头点通全流程并截图；
- 验收 6：冷启动彩排（setup → dev → 5 分钟走完）。
