# 接口契约（前后端唯一依据）

> 版本：v1（2026-10-22，含多角色）。前端、后端、验收脚本、E2E 均以此为准；改动需先改本文件。
> 服务：后端 `http://127.0.0.1:8080`，前端 `http://127.0.0.1:5173`（Vite 代理 `/api`）。

---

## 1. 通用约定

- 统一前缀 `/api`；请求/响应 `Content-Type: application/json; charset=utf-8`。
- 除 `POST /api/auth/login` 外，均需 `Authorization: Bearer <JWT>`。
- 成功：HTTP 200 `{ "code": 0, "message": "ok", "data": <payload> }`。
- 失败：HTTP 4xx/5xx `{ "code": <数字>, "message": "<中文提示>" }`。
- 字段一律 **camelCase**（DB 为 snake_case，由后端映射）；时间 `YYYY-MM-DD HH:mm:ss`；日期 `YYYY-MM-DD`；金额为 number（元，两位小数）。
- 错误码：`40001` 参数校验失败、`40101` 未登录/过期、`40102` 账号或密码错误、`40301` 无权限、`40401` 资源不存在、`40901` 当前状态不允许该操作、`50000` 服务器错误。
- JWT：HS256，payload `{ uid, username, role, name }`，有效期 12h。

### 角色码

`SHIPPER` 货主 / `MTO` 调度 / `CARRIER` 公路承运人 / `TERMINAL` 港站 / `SETTLEMENT` 结算。

## 2. 状态机与权限矩阵

### 订单 `order.status`

| 值 | 中文 | 进入条件 |
|---|---|---|
| `CREATED` | 待调度 | 货主下单 |
| `DISPATCHED` | 已调度 | MTO 调度完成 |
| `IN_TRANSIT` | 运输中 | 公路段已提货 / 港站确认进场 |
| `ARRIVED` | 已到达 | 铁路段完成 |
| `SIGNED` | 已签收 | 货主签收 |
| `BILLED` | 已出账 | 结算生成账单 |

### 运单 `waybill.status`

`PENDING 待发运 → IN_TRANSIT 运输中 → ARRIVED 已到达 → SIGNED 已签收`

### 分段 `waybill_segment.status`

`PENDING 待接单/待进场 → ACCEPTED 已接单 → IN_TRANSIT 运输中 → ARRIVED 已到达 → COMPLETED 已完成`
（`ARRIVE` 动作原子完成 `ARRIVED → COMPLETED`；禁止跨段推进）

### 节点动作权限（`POST /segments/{id}/status`）

| action | 允许角色 | 限定 | 合法前置状态 | 结果 |
|---|---|---|---|---|
| `ACCEPT` | CARRIER | 公路段且 `carrierUserId == 我` | PENDING | ACCEPTED |
| `DEPART` | CARRIER | 公路段且 `carrierUserId == 我` | ACCEPTED | IN_TRANSIT |
| `ARRIVE` | CARRIER | 公路段且 `carrierUserId == 我` | IN_TRANSIT | COMPLETED |
| `GATE_IN` | TERMINAL | 海运/铁路段 | PENDING | IN_TRANSIT |
| `ARRIVE` | TERMINAL | 海运/铁路段 | IN_TRANSIT | COMPLETED |

- 顺序约束：第 `n` 段未 `COMPLETED` 时，第 `n+1` 段不可 `GATE_IN`（`40901`）。
- 订单联动：首次 `DEPART`/`GATE_IN` → `IN_TRANSIT`；铁路段完成 → `ARRIVED`。
- 运单联动：首次 `DEPART`/`GATE_IN` → `IN_TRANSIT`；铁路段完成 → `ARRIVED`。
- 箱联动：`GATE_IN` 时可录箱况，箱 `EMPTY→GATE_IN`；海运到港 `ARRIVED`；签收 `DELIVERED`。

## 3. 数据模型（7 表，字段摘要）

- `user`：id、username、password_hash、display_name、role、created_at
- `orders`：id、order_no、shipper_id、status、cargo_name、cargo_weight、container_type、container_count、origin、destination、required_pickup_date、remark、created_at、updated_at
- `container`：id、order_id、container_no、type、seal_no、status、condition_text
- `waybill`：id、waybill_no、order_id、status、signer_name、signed_at
- `waybill_segment`：id、waybill_id、seq、mode(ROAD/SEA/RAIL)、carrier_code、carrier_name、carrier_user_id、start_node、end_node、planned_start/end、actual_start/end、accepted_at、status、cost_amount
- `track_point`：id、waybill_id、segment_id、seq、node_name、lng、lat、occurred_at、source(MOCK_GPS/MOCK_EDI/CARRIER_REPORT/TERMINAL_REPORT/MTO)、description
- `bill`：id、bill_no、order_id、waybill_id、total_amount、status、segment_breakdown(JSON)、issued_at、paid_at

字段细节见 `api/db/schema.sql`。

## 4. 接口定义

### 4.1 `POST /api/auth/login`

请求：`{ "username": "shipper01", "password": "demo123" }`

响应 `data`：
```json
{
  "token": "eyJhbGciOi...",
  "user": { "id": 1, "username": "shipper01", "displayName": "上海远洋物流（货主）", "role": "SHIPPER", "roleLabel": "货主" }
}
```
失败：`40102`。

### 4.2 `POST /api/orders`（货主下单）

请求：
```json
{
  "cargoName": "汽车配件",
  "cargoWeight": 18.2,
  "containerType": "40HQ",
  "containerCount": 1,
  "origin": "上海嘉定",
  "destination": "成都青白江",
  "requiredPickupDate": "2026-10-25",
  "remark": "演示订单"
}
```
校验：必填；`cargoWeight > 0`；`containerCount` 1–20；`containerType ∈ {20GP,40GP,40HQ,45HQ}`；日期不早于今天。
响应：同 `GET /orders/{id}` 的 `data`（`order.status = CREATED`）。
副作用：生成 `order_no = MO + yyyyMMdd + 4 位当日序号`，并按箱量生成 `container` 记录（箱号由订单 id 派生，保证唯一）。

- SHIPPER：自己的订单
- MTO：全部
- CARRIER：存在 `carrier_user_id = 我` 的分段的订单
- TERMINAL：`status ∈ (DISPATCHED, IN_TRANSIT, ARRIVED)` 的订单
- SETTLEMENT：`status ∈ (SIGNED, BILLED)` 的订单

响应 `data`：数组

```json
  {

    "billId": null, "billNo": null
```

### 4.5 `POST /api/orders/{id}/dispatch`（MTO 调度）

请求：`{ "roadCarrierCode": "AJ-001" }`
限 MTO；仅 `order.status = CREATED`，否则 `40901`。
副作用（单事务）：创建运单（`waybill_no = WB + yyyyMMdd + 3 位当日序号`）与 3 个分段：

| seq | mode | carrier | 起止 | cost |
|---|---|---|---|---|
| 1 | ROAD | 所选公路承运商（`carrier_user_id = 3`） | 上海嘉定工厂 → 上海洋山港 | 承运商报价 |
| 2 | SEA | COSCO-EDI / 中远海运（mock） | 上海洋山港 → 武汉阳逻港 | 5200 |
| 3 | RAIL | CR-95306 / 中铁集装箱（mock） | 武汉吴家山站 → 成都城厢站 | 8600 |

订单 → `DISPATCHED`；`planned_start/end` 由 `now` 顺延（公路 +2h/+8h，海运 +1d/+1d12h，铁路 +2d/+2d9h）。

响应 `data`：`{ "orderId": 12, "waybillId": 8, "waybillNo": "WB20261022001", "segments": [...] }`

### 4.6 `POST /api/segments/{id}/status`（节点上报/推进）

请求：`{ "action": "ACCEPT", "conditionText": "箱况良好，无破损" }`（`conditionText` 仅 `GATE_IN` 可选）
响应 `data`：`{ "segment": {...}, "orderStatus": "IN_TRANSIT", "waybillStatus": "IN_TRANSIT", "containers": [...], "newTrackPoints": [...] }`
错误：越权 `40301`；顺序/状态不符 `40901`；不存在 `40401`。

轨迹规则（后端保证确定性）：每次动作追加 1–3 个 `track_point`，
`ACCEPT`/`DEPART`/`ARRIVE` 的操作点 `source=CARRIER_REPORT`，`GATE_IN`/到港到站的港站点 `source=TERMINAL_REPORT`，
途中补点 `source=MOCK_GPS`（按段内节点线性插值），EDI mock 节点 `source=MOCK_EDI`；`seq` 按运单全局递增。
途中 GPS 补点的 `nodeName` 统一为「在途位置」，仅在业务节点（司机/港站/EDI/签收）保留真实节点名。

### 4.8 `POST /api/waybills/{id}/sign`（货主签收）

请求：`{ "signerName": "李经理" }`
限 SHIPPER（订单所属货主）；需全部分段 `COMPLETED` 且运单 `ARRIVED`，否则 `40901`。
副作用：运单 → `SIGNED`（记录签收人/时间）；订单 → `SIGNED`；箱 → `DELIVERED`；追加一条 `source=MTO` 的签收轨迹（终点坐标）。
响应 `data`：`{ "waybill": {...}, "order": { "id": 12, "status": "SIGNED", "statusLabel": "已签收" } }`

### 4.9 `POST /api/orders/{id}/settle`（结算出账）

限 SETTLEMENT；需 `order.status = SIGNED` 且无账单，否则 `40901`。
副作用：生成 `bill`（`bill_no = BL + yyyyMMdd + 3 位当日序号`，`segment_breakdown` 为各段明细，`total_amount = Σ cost_amount`）；订单 → `BILLED`。
响应 `data`：同 4.10 的完整账单结构。

## 8. curl 快速自检（README 会收录）

```powershell
# 登录
curl.exe -s -X POST http://127.0.0.1:8080/api/auth/login -H "Content-Type: application/json" --data-raw "{\"username\":\"shipper01\",\"password\":\"demo123\"}"
```
